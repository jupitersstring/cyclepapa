
## Data durability (READ THIS — protects against sandbox resets)

Claude-Code-on-the-web runs in an **ephemeral container**: `cache/` is gitignored
and is destroyed on every reset. The fetched fundamentals (~hours of rate-limited
Yahoo calls) therefore live in TWO places:

- `cache/`  — working copy, **ephemeral**, regenerated by the pipeline.
- `data/`   — **durable, git-tracked snapshot**: `universe.parquet`,
  `fundamentals.parquet`, `scored.parquet`, `raws.tar.gz` (every raw JSON),
  `surprises.json`, `web_verdicts.csv`, `top5_by_region.csv`, `manifest.json`.

**Recovery is automatic.** A SessionStart hook (`.claude/hooks/restore_cache.sh`,
wired in `.claude/settings.json`) detects a fresh/wiped sandbox and runs
`python scripts/snapshot.py restore`, rehydrating `cache/` (parquets + the raws
archive) from `data/` with **zero re-fetching**. It is a no-op when the cache is
already populated.

**The discipline that keeps the snapshot current (do this after any fetch):**

    python scripts/snapshot.py save     # cache/ -> data/  (use --with-raws after new fetches)
    git add data/ && git commit -m "Refresh data snapshot" && git push

If you fetch new data and DON'T save+commit it to `data/`, it is NOT protected.
`snapshot.py status` shows the current vintage; `restore` rehydrates after a reset.
