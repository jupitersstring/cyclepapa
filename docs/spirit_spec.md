# Spirit-score specification for the non-tiered archetypes

This covers 147 archetypes: every `arch_*` in `archetype_tags.py` except the 20 that already have `_SPIRIT` entries. The machine-readable spec is in `spirit_spec.json`.

**How a score is computed.** Same rule as _spirit() in archetype_tags.py: rank each lens*sign within the archetype's current members (pct), require >= 5 non-null members per lens and >= ceil(n_lenses/2) lenses per name, spirit = mean of available lens ranks. When 'blend' is set, spirit = w0*spirit(groupA) + w1*spirit(groupB); group entries are lens exprs whose signs come from 'lenses'.

**Lens grammar.** Each lens is [expr, sign]; sign +1 higher-is-better, -1 lower-is-better. expr is a validated column or an arithmetic expression over validated columns with + - * / and helpers: pos(x)=x.where(x>0) (a negative multiple is not cheap); abs(x); nz(x)=x.fillna(0) (only for analyst counts, where compute() treats missing coverage as zero); days_since(date_col)=days from the date to today. MIDCYC = normalized_ebitda/normalized_revenue*revenue_ttm (the margin-based mid-cycle EBITDA compute() already uses).

**Validation.** Every identifier was checked against the headers of archetype_tags.csv, asymmetry_global.csv, the compute() overlays (ts_, tc_, fqx_, fq_, fmp_st_, fmp_seg/geo, bs_, sent_, evt_ renamed from ev_, fmp_enrichment, fmp_dynamics, fmp_institutional, EDGAR side files) or a df[...] assignment / _fmp_fill in archetype_tags.py; every expression was evaluated on the frame compute() builds (46,526 rows; compute() re-run 2026-09-26 ~15:50 UTC on a scratch copy of the current archetype_tags.py and live CSVs). _validation holds n_core, the share of current members for which the spirit can be computed, per-lens coverage, the largest pairwise Spearman correlation between lens ranks, and each lens's Spearman correlation with the resulting spirit.

**How lenses were chosen.** Each lens reads one independent angle of the archetype's own thesis, taken from the source documents or, where none covers the archetype, from the comment on its rule in `archetype_tags.py`. Where the thesis has a duration element, a lens rewards length (streaks, years positive, months of net-debt decline, base length, dividend-raise streak) or more than one horizon (1y and 2y lags, TTM and 5y capex). A name that shows more of the evidence for longer ranks higher; no single maximum decides it. Every lens uses a ratio, yield, growth rate, rank or a USD-denominated level. No lens is an unrelated negative gate. Survivability lenses (net cash, runway) appear only where the source names survival as part of the thesis.

Source keys: COMP = archetype_compendium, MAR = master_archetype_reference, WO = Wolf of Oakville / Oak Bloke, LC = Liger Cub / Byron Street, PER = Pernas Research, CODE = the rule's own comment in archetype_tags.py.

**Coverage column.** `n` is the current core size. `spirit` is the share of the current members that get a score. Per-lens coverage appears only for lenses under 60%.

## Binary, tiny-core and caveated archetypes

- **special_situation: binary, no lenses.** The true measure is the deal spread (offer / price − 1) and time to close. Neither is in the data. The nearest available proxy is how recent the filing is: `days_since(evt_merger_proxy_date)` or `days_since(evt_tender_date)`.
- **Cores under 5 members, so the spirit is NaN under the ≥5 rank rule:** wolf_emerging (2), spinoff_quality (2), spinoff_asset (2), post_reorg (2), spinoff_value (3), xr_stake_fv_gap (4). Lenses are still specified. For the three spin-offs, rank the family jointly (pool the spin cores) or relax the minimum.
- **Thin cores (5–12), usable but noisy:** xr_monetization_trifecta (5), lifo_hidden_reserve (7), pension_overfunded (9), xr_investment_remark (11), cluseau_buyback_accel (12).
- **xr_peer_margin_gap:** its defining gap (sector-median op margin minus own) exists only as a local `_margin_gap_x46` in `compute()`. The proposed lens is `peer_margin_gap` (+1), which needs a one-line `df[...] =` in `compute()`. It is listed under `proposed_lenses` and not used.
- **Deliberately correlated horizons (duration principle):** lindy_growth uses 5y and 3y CAGR (ρ 0.88), and overdepreciated_assets uses TTM and 5y-average capex/D&A (ρ 0.90). These are the same fact at two horizons, kept on purpose so that persistence is rewarded.
- **Lenses that disagree with the rest of the core (ρ with spirit < 0.1):** nol_shell net cash (−0.16), oak_resource_leverage price_pct_of_5y_range (0.09), xr_latent_bath_floor cfo_yield (0.02), lifo_hidden_reserve reserve/mcap (n=7). Each is a separate leg the source requires (survivability, bought on weakness, the bath was non-cash, size of the reserve), so they were kept as real trade-offs rather than dropped for agreement.
- **Sparse lenses kept because each archetype has enough others to meet the half-of-lenses rule:** wolf_seal evt_surprise_4q and evt_react_last (~28%), templeton sent_buy_share (40%), tax_efficient and tax_verified fq_cash_tax_rate (36–41%), xr_latent_inflection_floor fcf_eta_quarters (29%), kpi_threshold fqx_inc_ebit_margin (50%).
- **Currency:** levels are always divided by a same-currency denominator. EDGAR USD items are divided by `market_cap_usd`. Master-currency items are divided by `market_cap`, `revenue_ttm`, `equity` or `enterprise_value`, which is the convention `compute()` itself uses. `market_cap_usd` appears as a lens only in xr_gaap_profit_crossover, where index/mandate size is the thesis.
